## 1. Key vocabulary and conflict table

- [ ] 1.1 Reference `SharpHook` from `Pisum.Whisper.Core` and add `SharpHook.Testing` 8.0.0 to `Directory.Packages.props`, referenced from `Pisum.Whisper.Core.Tests`. `SharpHook` itself is already pinned by change 1. Verify: `dotnet build Pisum.Whisper.slnx` stays at 0 warnings, and `dotnet build src/Pisum.Whisper.App -r osx-arm64` still restores.
- [ ] 1.2 Add `Core/Hotkeys/KeyCodeMap.cs` with the forward table — letters, digits, `F1`-`F12`, arrows, numpad, editing and punctuation keys — mapping case-insensitively to `SharpHook.Data.KeyCode`, including the reference's aliases (`ESC`/`ESCAPE`, `DEL`/`DELETE`, `INS`/`INSERT`, `PGUP`/`PAGEUP`, `PGDN`/`PAGEDOWN`, `UP`/`ARROWUP`, `RETURN`/`ENTER`, and the punctuation characters themselves such as `-`/`MINUS` and `[`/`BRACKETLEFT`). `TryParse`-shaped; it never throws. Verify: unit tests over every row of the reference's `parse.rs` table asserting the expected `KeyCode`, one asserting mixed case resolves identically, and one asserting an unknown name returns false rather than throwing. Note SharpHook's names differ from the reference's (`Vc1` not `Digit1`, `VcOpenBracket` not `BracketLeft`, `VcEquals` not `Equal`, `VcNumPad1` not `Numpad1`, `VcUp` not `ArrowUp`) — this is a re-expression, not a transcription.
- [ ] 1.3 Add the modifier alias table to `KeyCodeMap`: `ctrl`/`control`, `alt`, `shift`, and `meta`/`super`/`win`/`cmd`/`command`, each group resolving to one modifier, matched case-insensitively. Verify: unit tests asserting all five meta spellings resolve identically, that `Control` and `ctrl` do, and that an unknown modifier returns false.
- [ ] 1.4 Add the reverse direction — one canonical name per `KeyCode`, covering exactly the keys the forward table covers. Verify: unit test round-trips every canonical name through parse and back to the same `KeyCode`; a second asserts that a `KeyCode` outside the vocabulary (use `VcF13`) reports no name rather than returning a fabricated one.
- [ ] 1.5 Add `Core/Hotkeys/ConflictDetector.cs` with the reference's seventeen-entry system table and order-insensitive, case-insensitive comparison over normalised modifiers. Pure function, no dependencies. Verify: unit tests for an exact match, for the same modifiers in a different order, for a non-conflicting binding, and for `Ctrl`+`Shift`+`Space` — the default binding, which must report no conflict.

## 2. The chord and the matcher

- [ ] 2.1 Add `Core/Hotkeys/HotkeyChord.cs` — an immutable compiled binding holding a normalised modifier group set and a `KeyCode` — with a factory that compiles a `HotkeyBinding` through `KeyCodeMap`. Verify: unit tests asserting `["Ctrl","Shift"]`+`Space` compiles to the Ctrl and Shift groups plus `VcSpace`, and that an unrecognised token fails to compile without throwing.
- [ ] 2.2 Implement mask normalisation: fold an `EventMask` into the four modifier groups by testing `(mask & EventMask.Ctrl) != 0` and its siblings, discarding `NumLock`, `CapsLock`, `ScrollLock` and `Button1`-`Button5`. Verify: unit tests asserting a right-hand modifier matches a left-hand configuration, that Caps Lock on and a held mouse button both still match, and one asserting `HasFlag(EventMask.Ctrl)` would have failed the right-hand case — the trap this normalisation exists to avoid, since `EventMask.Ctrl` is `LeftCtrl | RightCtrl`.
- [ ] 2.3 Implement the match predicate: exact equality of the group set, not a superset. Verify: unit tests asserting the configured combination plus an extra modifier does not match, and that a modifier-less binding does not match while a modifier is held.
- [ ] 2.4 Implement the engage/disengage state machine — engage on the main key's press when the groups match, coalesce auto-repeat presses while engaged, disengage on release of the main key or of any required modifier. Verify: unit tests for a single press/release pair, for twenty repeat presses producing exactly one edge, for a modifier released first, for the main key released first, and for the remaining keys released afterwards producing no second release.
- [ ] 2.5 Implement the suppression decision: suppress both edges of the main key when the chord matches, never suppress a modifier key, never suppress an unmatched key. Verify: unit tests asserting `SuppressEvent` is true on the main key's press and release, and false on every modifier event and on an unrelated key.
- [ ] 2.6 Ignore simulated events before matching, using `HookEventArgs.IsEventSimulated`. Verify: unit test posting a simulated press of the configured combination and asserting no edge is reported — this is what keeps change 7's synthetic paste from being observed.

## 3. The hook service

- [ ] 3.1 Add `Core/Hotkeys/IGlobalHotkeyService.cs` (`Pressed`, `Released`, the availability state, and the capture entry point) and `GlobalHotkeyService` over a `SimpleGlobalHook` constructed from an injected `IGlobalHookProvider`. Verify: unit test builds the service over `SharpHook.Testing`'s provider, posts a matching combination, and asserts one `Pressed` and one `Released`.
- [ ] 3.2 Implement the hook-thread-to-consumer seam: an unbounded `Channel<HotkeyEdge>` with `SingleWriter` and `SingleReader`, written from the hook handler and drained by one dispatch loop that raises the events. The hook handler does nothing but match, set `SuppressEvent` and `TryWrite`. Verify: unit test whose `Pressed` handler blocks for two seconds asserts the hook handler returned promptly and that the following `Released` was still delivered in order — this test fails if the events are ever raised directly on the hook thread.
- [ ] 3.3 Implement the lifecycle as `IHostedService`: `StartAsync` calls `RunAsync(GlobalHookType.Keyboard, useBackgroundThread: true)`, `StopAsync` calls `Stop`, `Dispose` disposes the hook and completes the channel. Verify: unit tests asserting the hook is running after start and not after stop, and that the dispatch loop terminates rather than leaking a thread.
- [ ] 3.4 Synthesise a `Released` whenever the service is engaged and observation ends — on `HookDisabled`, on `StopAsync` and on `Dispose`. Verify: unit tests for each of the three paths, posting a press and then ending observation without a key-up, asserting exactly one `Released`.
- [ ] 3.5 Handle a `HookException` from `RunAsync` as non-fatal: log at `Error`, leave the application running with no binding observed, and expose the unavailable state. Distinguish `UioHookResult.ErrorAxApiDisabled` (never granted) from `ErrorAxApiRevoked` (withdrawn while running) with separate messages, since the remedies differ. Verify: unit tests with a provider returning each result assert no exception escapes startup, that the state reports unavailable, and that the two log messages differ.
- [ ] 3.6 Subscribe to `SettingsStore.Changed`, recompile the chord and publish it with a `Volatile.Write` without restarting the hook; emit `Released` first if the previous chord is engaged. Verify: unit tests asserting the new combination matches and the old one does not after a save, that the hook was never stopped, and that a rebind while engaged reports a release before the swap.
- [ ] 3.7 Fall back to the default combination — Ctrl+Shift+Space, or Cmd+Shift+Space on macOS — when the configured binding fails to compile, logging at `Warning` with the offending token named. Verify: unit tests asserting the default is observed, that the warning names the bad token, and that the settings file is byte-identical afterwards, since `SettingsStore` owns every write.
- [ ] 3.8 Implement the capture entry point: while capture is active the configured chord is not matched and no edge is reported; capture completes on the first full combination, reporting it as modifier names and a key name through `KeyCodeMap`'s reverse direction; a key with no canonical name is reported as unnameable rather than as a combination. Cancellation resumes normal matching. Verify: unit tests for a captured combination, for capturing the currently configured binding without reporting an edge, for cancellation restoring matching, and for an unnameable key.
- [ ] 3.9 Route libuiohook's own diagnostics into `ILogger<GlobalHotkeyService>` via `LogSource.RegisterOrGet(SharpHook.Data.LogLevel.Warn)`, disposing the source with the service. `Warn` and above only — the lower levels log per event. Verify: unit test asserts the source is registered and disposed; manual step confirms a deliberately failed hook start produces a libuiohook message in `~/.pisum-whisper/logs/`.
- [ ] 3.10 Assert the no-keystroke-logging rule holds. Verify: unit test wires the change 3 `RecordingSink` at `Verbose`, posts fifty non-matching key events through the test provider, and asserts no emitted message or property contains a key code or key character; a second posts the configured combination and asserts the binding and the edge are named and nothing else is.

## 4. Composition and conventions

- [ ] 4.1 Add `AddGlobalHotkey` in `Core/Hotkeys/GlobalHotkeyServiceCollectionExtensions.cs` registering `GlobalHotkeyService` as a singleton, with `IGlobalHotkeyService` and `AddHostedService` both resolving that same instance, and call it from `Program.cs` after `AddFileLogging`. One instance only — SharpHook corrupts its native state if two hooks run in one process. Verify: unit test resolves `IGlobalHotkeyService` and the hosted service from a built host and asserts they are the same object; run the app and confirm a log line reports the observed binding.
- [ ] 4.2 Document the two rules this change establishes in `CLAUDE.md`, alongside change 3's logging rules: nothing but matching runs on the hook thread, because Windows silently removes a hook that exceeds `LowLevelHooksTimeout` and macOS disables an unresponsive tap; and no key that is not the configured binding is ever logged, at any level. Verify: both rules are written down before change 8 adds the first consumer of this seam.
