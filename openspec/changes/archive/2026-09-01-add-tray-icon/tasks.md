- [x] 2.2 Map `DictationState` to icon with an exhaustive `switch` expression over all three values, so that adding a fourth state later is a compile error rather than a silent fall-through to idle. Verify: `dotnet build Pisum.Whisper.slnx` at 0 warnings — with warnings-as-errors on, a non-exhaustive switch expression is the failure, which is the point of writing it as one. **Written and corrected 2026-09-01:** a bare three-arm switch expression does *not* build here. `CS8524` — the *unnamed* enum value, `(DictationState)3` — fires on every arm-complete enum switch expression and warnings-as-errors rejects it, so the task's premise that only a fourth state would fail was wrong. It is suppressed with a local `#pragma warning disable CS8524` rather than answered with a `_ =>` arm: a discard arm silences `CS8509` along with it and turns a fourth state from a build failure into a runtime one. ## 3. Wiring and lifecycle

- [x] 3.1 Replace the one-item menu with the reference's three: Settings, `NativeMenuItemSeparator`, Quit. Settings logs at `Debug` and returns until change 10 gives it a window; Quit keeps calling `desktop.Shutdown()`. Verify: manual, covered by 4.1 — all three items present, Settings does nothing visible, Quit exits with code 0. **Written 2026-09-01;** the manual check is 4.1's and outstanding.
- [x] 3.2 Resolve `DictationOrchestrator` from `IServiceProvider` in `OnFrameworkInitializationCompleted`, which runs after `host.Start()`, and subscribe to `StateChanged` and to `SettingsStore.Changed`. Marshal both through `Dispatcher.UIThread.Post`: `StateChanged` is raised on a pooled thread and `Changed` on whichever thread called `Save`, which will be change 10's UI thread. `Post` preserves order at equal priority, so a fast dictation's `Idle` cannot overtake its own `Transcribing`. `Changed` is subscribed here even though **nothing in the application can raise it until change 10** — `Save` is its only source, `Load` writes through `Write`, and there is no file watcher — because `OnExit` has to account for the subscription either way and change 10 needs it the day it opens the window. Verify: manual, covered by 4.1 — hold the hotkey through a full dictation and watch the icon move idle → recording → transcribing → idle, in that order. The `Changed` half is unverifiable in this change by construction, not by omission. **Written 2026-09-01;** the manual dictation check is 4.1's and outstanding.
- [x] 3.3 Seed the first icon from `DictationOrchestrator.State` instead of assuming `Idle`, as the last step of 3.2. The orchestrator subscribes to the hotkey in its **constructor** — its `StartAsync` is `Task.CompletedTask` — so it is armed from `host.Start()`, before this method exists, and a hotkey pressed during Avalonia's platform initialisation opens a recording the tray would otherwise misreport as idle until that dictation ended. `Post` the seed **after** both subscriptions and read `State` inside the callback, not at post time: that puts it in the same queue at the same priority as every real transition, so it can only ever lose to something newer. Do **not** read `State` first and assign `Icon` directly before subscribing — that inverts the race rather than removing it, losing any transition that lands in between. `State` takes the orchestrator's own lock, so reading it from the UI thread is safe. Verify: by inspection — the seed is posted after both subscriptions and reads `State` inside the callback; plus 4.1's ordinary launch still comes up idle. The race itself is deliberately **not** in the manual script: reproducing it needs a hotkey press inside Avalonia's initialisation window, which is why the ordering is written to be correct by construction rather than tested. **Written and inspected 2026-09-01:** the seed is posted after both subscriptions and reads `State` inside the callback.

## Not in this change

Recorded so they are not mistaken for oversights, each with its owner:

- **First-run discoverability.** Windows 11 files a new tray icon into the hidden overflow, and on notched MacBooks a menu bar extra can be pushed under the notch. Neither has an API fix; both are change 11's notification transport, gated on the `SettingsStore.IsFirstLaunch` flag that already exists.
- **Rendering `HotkeyAvailability.Failed`.** The macOS no-Accessibility case starts the app with a dead hotkey and says nothing. The tray is the only surface that could say so, but it is not a `DictationState` and a fourth icon would widen this change past its proposal. Change 11.
- **Automated tests.** There is no `tests/Pisum.Whisper.App.Tests` and `Avalonia.Headless.XUnit` is deliberately unreferenced until change 10. `design.md` records why neither standing it up early nor inventing a `Core` type to test was taken, and that this is the weakest part of the change.
- **Verifying that the tooltip follows a preset change.** The `SettingsStore.Changed` subscription ships here (task 3.2), but `Save` is its only source and nothing calls `Save` at runtime until change 10's settings window, so the refresh cannot be made to fire. The spec's *The active preset changes* scenario is satisfied by construction and proven in change 10; `design.md` records why the wiring was not deferred alongside the check.
- **`TrayIcon.Clicked`.** Left-click opening the settings window is change 10's, once there is a window to open.
