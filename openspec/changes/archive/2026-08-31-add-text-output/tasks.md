## 2. The delivery sequence

Everything in this group is `Core/Output/TextOutput.cs`, unit-tested in `Core.Tests/Output/` over a
fake `ISystemClipboard` and `SharpHook.Testing`'s `TestProvider`. No task here needs a clipboard, a
keyboard or a platform. Give `TextOutput` an internal constructor taking the two delays and the
macOS/Windows selection, the same shape `GlobalHotkeyService`'s test constructor already uses, so
the tests neither wait a second nor depend on the host operating system.

- [x] 2.1 Implement steps 1-5 of the sequence: read the previous text (best effort — a throwing `TryGetText` logs and continues with nothing to restore), write the transcript, wait 50 ms, send the paste, and return `Pasted` or `ClipboardOnly` from the `UioHookResult`. Verify: unit tests asserting the transcript reached the clipboard, that four events were posted, that a `PostEventResult` other than `Success` yields `ClipboardOnly`, and that a clipboard whose read throws still delivers.
- [x] 2.2 Implement the keystroke shape: modifier press, `VcV` press, `VcV` release, modifier release, with `VcLeftControl` on Windows and `VcLeftMeta` on macOS, and a 30 ms pause after every edge on macOS only. Verify: unit tests over the internal constructor asserting the exact ordered `PostedEvents` for both platform selections on either host, and that the Windows selection posts no pauses.
- [x] 2.3 Implement step 0 — trim leading and trailing whitespace from the transcript — and reject what is left when it is empty with `ArgumentException`, before the clipboard is touched. Verify: unit tests asserting a transcript ending in `\n` reaches the clipboard without it, that line breaks between words survive, and that whitespace-only text is rejected with the clipboard never read or written and no event posted.
- [x] 2.4 Implement step 3 — consult `IPasteProbe` after the transcript is written and before the keystroke; `false` returns `ClipboardOnly` with no events posted and no restore. Verify: unit tests with a refusing probe asserting the outcome, that `PostedEvents` is empty, that the transcript is still on the clipboard afterwards, and that an accepting probe posts the keystroke as normal.
- [x] 2.5 Translate a failed clipboard write into `TextOutputException` with a message that names what failed, and send no keystroke afterwards. Verify: unit tests with a fake whose `SetText` throws, asserting the exception type, that its message is non-empty, and that `PostedEvents` is empty.
- [x] 2.6 Implement guard 1 — a non-`Success` paste returns `ClipboardOnly` immediately, leaving the transcript on the clipboard and performing no restore. Verify: unit test asserting the clipboard still holds the transcript afterwards and that no second write occurred.
- [x] 2.7 Implement steps 6-7 with guards 2 and 3 — wait the restore delay, then restore the previous text only if `TryGetText` still returns exactly the transcript and the previous contents were text. Verify: unit tests for the restore happening, for a clipboard changed under us leaving the newer contents alone, for a `null` previous read skipping the restore, and for a second delivery's transcript standing the first delivery's restore down.
- [x] 2.8 Implement the cancellation rule — once the transcript has been written, a cancelled token shortens the restore wait to nothing instead of abandoning the sequence, and the guards still decide what is restored; cancellation before the write stops with the clipboard untouched. Verify: unit tests cancelling between the paste and the restore asserting the previous text is back and that the call returned without waiting the full delay, and cancelling before the write asserting the clipboard was never modified.
- [x] 2.9 Enforce the logging rule: the transcript, and the previous clipboard contents, are never written to the log at any level; the character count, the paste result and the reason a restore was skipped are. Verify: unit test wiring change 3's `RecordingSink` at `Verbose` through a full delivery, asserting no emitted message or property contains either string and that the count and outcome are present — the same shape as change 6's task 3.10.

- [x] 2.10 Serialise deliveries with a `SemaphoreSlim(1, 1)` held across the whole sequence, released in a `finally`, so a second delivery cannot read the first one's transcript and mistake it for the user's clipboard. Verify: unit test starting two deliveries over one fake clipboard with the restore delay set long enough to overlap, asserting the original contents are what remain at the end and that the second delivery's restore never wrote a transcript; a second test asserts the gate is released after a delivery that threw.
